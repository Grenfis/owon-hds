# OWON HDS272S — пульт

Программа для управления осциллографом OWON HDS272S по USB: осциллограф, генератор и мультиметр в одном окне. Замена фирменной программы на Java. Сделана на Wails (Go + Vue).

## Подключение

1. На приборе: **System → F4 → USB → HID**.
2. Нужен драйвер libusb-win32 (`libusb0.dll` в `C:\Windows\System32`). Его ставит фирменная программа OWON.
3. Запустите `owon-hds.exe` и нажмите «Подключить по USB».

Без прибора работает «Имитатор»: CH1 показывает выход генератора, CH2 — тот же сигнал после RC-фильтра 10 кГц.

## Сборка

Из WSL или Linux, для Windows:

```sh
wails build -platform windows/amd64 -skipbindings
```

Результат: `build/bin/owon-hds.exe`.

Интерфейс можно отлаживать в браузере, без Wails:

```sh
cd frontend && npm run build && cd ..
go run ./cmd/owon-web            # http://127.0.0.1:34199, USB только в Windows
```

## Устройство

- `internal/hds` — протокол: кадры SCPI, разбор заголовка осциллограммы, измерения.
- `internal/usb` — доступ к libusb0.dll без CGO.
- `internal/sim` — имитатор прибора.
- `internal/app` — цикл опроса, очередь команд, привязки для интерфейса.
- `cmd/owon-web` — те же привязки через HTTP и SSE для работы в браузере.
- `cmd/owon-probe` — утилита для проверки протокола: печатает сырые ответы прибора.
- `frontend` — интерфейс на Vue.

Заводские и калибровочные команды (`:SERial`, `:Selfcorrec`, `:AUTocalibration`, `:PRACTISE`, `:DOWNload`, `:VIDEO`, `:VOLFULL`) программа не отправляет, даже из консоли.

## Что известно о протоколе

Проверено на HDS272S с прошивкой V8.8.2:

- Команды установки уходят без терминатора, запросы `:DATa` с `\r\n`. Ответ на запрос приходит за 10–30 мс.
- Кадр: 600 отсчётов, по одному знаковому байту, 50 на деление по горизонтали и 25 на деление по вертикали. АЦП чередующиеся, поэтому у соседних отсчётов бывает разница в 1 и одиночный выброс на фронте.
- Масштаб в заголовке и в `:CH1:SCALe` дан с учётом щупа («1.00 V» при щупе 10× — это 1 В/дел на экране).
- Уровень синхронизации задаётся в вольтах и округляется до 1/25 деления. Ноль прибор показывает как «0.00pV».
- `HOFFSET` в заголовке в отсчётах (25 на деление), `:HORizontal:OFFSet` в делениях. Положительный сдвиг уводит точку синхронизации влево.
- Пути синхронизации: `:TRIGger:SINGle:EDGe:SOURce`, `:TRIGger:SWEep`, `:TRIGger:COUPling`. Пути `:TRIGger:SINGle:SOURce` и подобные прибор не знает.
- В заголовке есть частота каждого канала (`FREQUENCE`), её считает сам прибор.
- Команду без аргумента прибор молча игнорирует: автонастройка работает только как `:AUToseton ON`.
- После `:CH<n>:SCALe` следующий запрос осциллограммы ждёт около 1.1 с, после `:AUToseton ON` около 1.7 с. Команды генератора, развёртки и смещения задержки не дают.
- На быстрых развёртках (1 мкс/дел) прибор отвечает медленнее, около 50 мс на запрос, и кадров получается около 9 в секунду.
- `:DMM:MEAS?` присылает голое число без единицы («0.0000e+00»).

Ещё не проверено: мультиметр на его собственном экране, включение выхода генератора, ответ на спад (`FALl` или `FALL`).
